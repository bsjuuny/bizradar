# BizRadar

B2B SaaS MVP for IT/SI companies (5-50 employees) to discover public-sector IT
procurement opportunities (G2B bids/awards, gov support programs, official contests) and
see a per-company match score against each one.

## Architecture: two independent runtimes

```
Browser -> apps/web (Next.js, Railway) -> Supabase (Postgres + Auth, RLS)
Local PC -> worker (Python, PM2)        -> Public APIs (G2B/BizInfo/K-Startup) -> Ollama -> Supabase
```

`apps/web` and `worker` never call each other directly - they only share the Supabase
database. The worker collects/analyzes/matches and writes results; the web app only reads
them. This is deliberate: Ollama runs locally, and Railway must never depend on it. See
`docs/ARCHITECTURE.md` before changing anything that looks like it crosses this boundary.

## Tech stack

- `apps/web`: Next.js 16 (App Router), React 19, TypeScript, Tailwind v4, Supabase
  (`@supabase/ssr`), Vitest (unit), Playwright (e2e).
- `worker`: Python 3.12, pydantic-settings, apscheduler, httpx, supabase-py, run under PM2
  (`ecosystem.config.cjs`) as `worker/scheduler/main.py`.
- `supabase`: SQL migrations + RLS + seed data, managed via the Supabase CLI.

## Commands

Web (`cd apps/web`):
```
npm install
npm run dev
npm run lint && npm run typecheck && npm run test:run && npm run build
npm run test:e2e   # needs real Supabase project via .env.worker + apps/web/.env.local
```

Worker (repo root, venv active):
```
python -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"   # Windows
ruff check worker && ruff format --check worker && pytest && mypy worker
pm2 start ecosystem.config.cjs
```

Supabase (repo root):
```
npx supabase db push --dry-run
python supabase/tests/test_rls_phase1.py
```

## Key files/dirs

- `apps/web/src/app` - routes: `/signup`, `/login`, `/onboarding`, `/dashboard`,
  `/opportunities` (Project Radar), `/settings`, `/market` (admin only), `/api`.
- `apps/web/src/lib` - `dal.ts` (data access), `supabase/` (client/server/admin clients),
  `features.ts` (`isPlatformAdmin`, feature flags), `match-explanation.ts`.
- `worker/collectors` - `g2b.py`, `g2b_awards.py`, `kstartup.py`,
  `data_go_kr_challenges.py`.
- `worker/ai` - `AIProvider` interface (`base.py`), `OllamaProvider` (only
  implementation), `rule_filter.py`, `schemas.py`.
- `worker/matching/engine.py` - deterministic rule-based Match Engine (not an LLM call).
- `worker/jobs` - scheduled units (`g2b_job`, `analyze_job`, `match_job`, `digest_job`,
  `challenge_job`, etc.), wired up in `worker/scheduler/main.py`.
- `supabase/migrations` - applied in filename (timestamp) order; additive only, no edits
  to already-applied migrations.
- `fixtures/` - recorded API responses for `DATA_MODE=mock` (g2b, bizinfo, kstartup,
  challenges).
- `docs/ARCHITECTURE.md`, `docs/DATABASE.md`, `docs/DATA_PIPELINE.md`,
  `docs/CHALLENGES.md`, `docs/TESTING.md` - read before nontrivial changes; kept in sync
  with what's actually implemented.

## Gotchas / conventions

- `apps/web/AGENTS.md` and `apps/web/CLAUDE.md` are auto-generated by `next dev`
  (Next.js 16 agent-rules block) - not project docs, do not hand-edit their content away;
  they get regenerated.
- `SUPABASE_SERVICE_ROLE_KEY` is worker-only, loaded from `.env.worker`. The one exception
  is `apps/web/src/lib/supabase/admin.ts`, used server-side only for company-approval
  actions gated by `requireAdmin()` - never reference it from a `"use client"` file.
  `authenticated` has no UPDATE privilege on `companies.approval_status` at all, by design.
- Data pipeline stages are separate and never overwritten in place: `RAW -> NORMALIZED ->
  ANALYZED -> MATCHED`.
- Match Engine (`worker/matching/engine.py`) is intentionally rule-based, not an LLM call
  - keep it deterministic and explainable; don't route it through `AIProvider`.
  `OllamaProvider` requires a local Ollama with `qwen3.5:9b` pulled; if unavailable the
  `analyze` job logs a failure and skips itself, it does not fail G2B collection.
  G2B collection and the `match` job have no external-service dependency.
  `/api/health` deliberately does not check Ollama - Railway must stay decoupled from it.
  `CHALLENGE` features are behind `FEATURE_CHALLENGE=true`.
- Testing policy (`docs/TESTING.md`): never skip tests to make them pass, never disable
  RLS to make a test pass.
- Windows PM2 uses `pythonw.exe`, not `python.exe`, for the worker interpreter (see
  comment in `ecosystem.config.cjs`) - avoids an auto-opened console window.
